# Tayaway Design Context

## Users

Friend groups planning trips, parties, and hangouts together. They're coordinating across busy schedules, splitting costs, voting on dates and options, and assigning tasks. Context is often quick check-ins on mobile between other activities, or longer planning sessions on desktop.

## Brand Personality

**Warm, reliable, smart.** Tayaway is the trustworthy, capable friend who makes group planning effortless. It's approachable without being juvenile, organized without being corporate.

## Emotional Goals

The interface should feel **warm and organized** — approachable but structured, reliable without being stiff. Users should feel confident that nothing is falling through the cracks, and that the tool respects their time.

## Aesthetic Direction

- **Visual tone:** Clean, fast, restrained — inspired by Linear's precision and minimalism, but warmer
- **References:** Linear (speed, restraint, beautiful simplicity)
- **Anti-references:** Enterprise tools (Jira, Salesforce — heavy, complex), social media (noisy, attention-grabbing)
- **Theme:** Light and dark mode, both equally important
- **Color palette:** Open to overhaul. Current amber identity is established but rose/cyan/neutrals can be rethought. Any new palette should feel warm, not cold or corporate

## Design Principles

1. **Clarity over cleverness.** Every element should communicate its purpose instantly. No ambiguity, no decoration for decoration's sake.
2. **Warm minimalism.** Strip away the unnecessary, but keep the result feeling human and approachable — not sterile.
3. **Speed is a feature.** Interactions should feel instant. Prioritize perceived performance, fast transitions, and responsive feedback.
4. **Mobile and desktop are equal citizens.** Design for both contexts simultaneously — quick mobile check-ins and longer desktop planning sessions.
5. **Accessible by default.** WCAG AA baseline, go beyond where it's easy. Don't gold-plate, but never compromise on fundamentals like contrast, keyboard nav, and screen reader support.

## Existing Design System

### Colors

- **Primary accent:** Amber (#d97706) — nav bar, brand identity, PWA theme
- **Action:** Rose (#f43f5e) — primary buttons, focus rings, checkboxes
- **Links:** Cyan (#06b6d4) — text links, secondary actions
- **Dark mode neutrals:** Stone palette (stone-700 to stone-900)
- **Light mode neutrals:** Gray palette (gray-100 to gray-900)

### Typography

- **Font:** Inter Variable (sans-serif)
- **Default body size:** `text-base` (16px). This is the baseline — don't go smaller without a reason.
- **Small text (`text-sm`, `text-xs`) is intentional, not default.** Only use for secondary metadata, timestamps, captions, or helper text. Never for primary content, labels, or anything users need to read quickly.
- **Headings:** semibold weight. `text-lg` for section headers, `text-2xl`–`text-3xl` for page titles.

### Components

71 Vue components using atomic Tailwind CSS utilities. Key patterns:

- AppButton (rose/gray/cyan/amber/danger variants, sm/md/lg)
- BaseCard (default/interactive/action/urgent variants)
- BaseModal (sm through 2xl, backdrop blur)
- Consistent focus-visible outlines (rose-500)
- HeadlessUI for accessible primitives (menus, disclosures, dialogs)

### Icons

Heroicons v2 (outline-24, solid-16, solid-24)

### Layout

- Sticky amber nav bar (h-16)
- max-w-7xl container, responsive padding (px-4 sm:px-6 lg:px-8)
- Cards with hover ring effects, active scale transforms
